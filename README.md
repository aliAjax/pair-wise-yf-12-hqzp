# 油站台账合并入库

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 流程验证：`npm run verify`（55 项端到端断言，覆盖队列/冲突/权限/续作/迁移）

数据保存在浏览器 localStorage，站点档案、盘点来源、批次、行、冲突台账、合并日志均持久化可续作。

## 入库流程规则

1. **CSV 入库**：表头 `站点名称,区域,库存L,营业状态,盘点时间`；可多选文件，解析后立即留存来源与批次（全部非法的文件不建记录）。
2. **同时到达排队**：同一次导入的多个文件归入同一「波次」，按读取时间逐批处理，前一批处理完再下一批。
3. **同站点合并**：库存按来源盘点时间取较新者（自动取值、留库存冲突待调度员批准）；营业状态未经员工确认前两版并存。
4. **冻结**：站点一产生冲突即冻结；波次内两批都完成（无失败行、无未决冲突）才解冻并重算统计。
5. **权限（越权直接拒绝）**：
   - 普通员工只能处理自己负责站点的**状态冲突**（二选一）；
   - 只有调度员能**批准合并**与**回滚**（回滚按合并前快照还原，站点重新冻结，可重新处理/批准）。
6. **失败续作**：写入失败的行保留错误原因，可就地修正后**只重试这一行**；已解析的批次与来源不丢，页面重载后排队批次继续跑。
7. **重复导入**：按文件内容指纹判重，重复文件不新增任何记录。
8. **多标签页**：同一时刻只有持写锁的标签页能写入（心跳过期可接管），其余标签页只读并通过 storage 事件实时同步，避免互相覆盖。
9. **旧数据迁移**：首次打开自动把旧版台账（`hxwlfront-21-station-map`）迁入新台账，逐条保留「旧版台账（自动迁移）」来源，只迁一次。

## 演示路径

1. 用顶部下拉切换身份（东区员工 刘建国 / 机场线员工 王敏 / 调度员 周调度）。
2. 点「演示：两个批次同时到达（早班 + 晚班）」：
   - 东区两站库存自动取晚班较新值；东区二站与机场站状态两版并存；
   - 机场快线站首次写入模拟失败 → 在批次面板点「只重试本站点」；
   - 切到员工处理本站状态冲突 → 切到调度员逐个批准 → 波次解冻、统计重算；
   - 调度员可对已批准冲突执行回滚。
3. 再次点同一演示按钮会提示重复导入、不新增记录。

## 目录

- `src/types.ts`：领域模型与权限错误
- `src/utils/csv.ts`：CSV 解析、校验、内容指纹
- `src/utils/leader.ts`：多标签页写锁协调
- `src/stores/ingest.ts`：入库/队列/冻结/冲突/批准/回滚/重试/迁移
- `src/components/`：TopBar、StatsBar、ImportPanel、WavePanel、ConflictLedger、StationArchive、MergeLogPanel
- `scripts/verify.ts` / `verify-migration.ts`：端到端流程验证
