# 油站台账入库（站点档案 · 冲突台账 · 批次续作）

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

把站点档案、冲突台账和批次接成可续作的入库流程，解决人工合并多份盘点 CSV 时多标签页互相覆盖、交班时库存与营业状态对不上的问题。数据保存在浏览器 localStorage（`hxwlfront-21-ledger-v1`）。

## 业务规则

- **批次排队**：一次 CSV 导入为一个批次，按读取时间排队，多批次顺序处理。
- **库存**：同站点取来源较新者（以盘点时间 / 读取时间判定），并保留来源批次。
- **营业状态**：未确认就留两版（旧版 ↔ 新版），站点冻结、冲突进台账。
- **权限**：普通员工处理归属自己的冲突；批准合并与回滚仅调度员可执行，越权直接拒绝并写入日志。
- **解冻重算**：冲突处理完、站点解冻后才重算统计；存在冻结站点时统计不重算。
- **失败续作**：导入失败只重试没写成功的站点，已写入的站点与来源留住；重复导入按内容哈希去重，不新增记录。
- **旧数据迁移**：首次打开时把旧台账（`hxwlfront-21-station-map`）迁入新台账，来源标记为「历史数据迁移」。

## 演示步骤

1. 首次打开自动迁移旧台账（东区一站、机场快线站，来源为历史数据）。
2. 「导入盘点 CSV」区载入示例批次 A、B（或选择 CSV 文件，可多文件）。
3. 批次 B 与 A 同站点：库存取较新来源，营业状态冲突 → 站点冻结、冲突进台账。
4. 切到「员工」身份，在冲突台账处理归属自己的冲突（采用旧版 / 新版 / 保持两版）。
5. 切到「调度员」身份，批准合并（或回滚）；越权操作会被拒绝。
6. 勾选「演示：故意让首个站点写入失败」再导入，批次变为「部分失败」，点「续作：重试失败站点」只重试未成功站点。
7. 再次导入同一文件 → 提示重复导入，不新增记录。

## 目录

- `src/stores/ledger.ts`：台账状态、批次排队、冲突与权限、续作、迁移、统计。
- `src/lib/csv.ts`：CSV 解析、内容哈希（去重）、示例数据。
- `src/components/`：`RoleBar`（身份与权限）、`ImportPanel`（导入与日志）、`BatchesPanel`（批次与续作）、`SitesPanel`（站点台账与来源）、`ConflictPanel`（冲突台账与批准 / 回滚）。
